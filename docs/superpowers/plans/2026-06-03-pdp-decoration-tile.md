# Customer PDP — Decoration Tile + Blank-Image Filter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the decoration the customer is buying explicitly visible via a new `DecorationTile` under the gallery, and stop the gallery from showing blank/wrong-colour master garment templates when a colour has real photos.

**Architecture:** Two independent, additive changes in `print-room-portal`, both pure presentation/data-shaping — no pricing or data-layer change. (1) A new presentational `DecorationTile` component fed by the already-computed, swatch-filtered `swatchVisibleDecorations`, mounted directly under `<ProductImageGallery>`. (2) A post-pass inside `resolveGalleryImagesForColour` that drops the priority-5 "master color-null primary-view base" image when ≥1 colour-specific image exists, with a never-empty guard. The live hero overlay (`ProductImageGallery`) is kept as-is (D3).

**Tech Stack:** Next.js (App Router — NOT vanilla Next.js; read `node_modules/next/dist/docs/` first), TypeScript, Vitest 2.1.9 + jsdom + `@testing-library/react` (`npx vitest run <path>`; setup file gives jest-dom + axe).

**Source spec:** [`2026-06-03-pdp-decoration-tile-and-blank-image-filter-design.md`](../specs/2026-06-03-pdp-decoration-tile-and-blank-image-filter-design.md). The "blank product image" definition is **RESOLVED** (§11): master-scope, `color_swatch_id == null`, primary-view base image (priority-5 rung) — so the blank filter is unblocked, both tasks ship.

```tsx
import type { DecorationOption } from '@/lib/shop/decorations'

/**
 * Presentational tile shown under the PDP gallery. Renders one image card per
 * decoration the customer is buying for the selected colour (snapshot mockup
 * when present, else the raw artwork) with its name + position. Display-only:
 * decoration price flows through ProductDetailClient and is suppressed for
 * manual_final items (Spec B) — the tile is unaffected by that.
 */
export function DecorationTile({
  decorations,
  productName,
}: {
  decorations: DecorationOption[]
  productName: string
}) {
  if (decorations.length === 0) return null

  return (
    <div className="mt-4">
      <h2 className="mb-2 text-sm font-medium text-gray-700">Decoration</h2>
      <ul className="grid grid-cols-2 gap-3 sm:grid-cols-3">
        {decorations.map((d) => {
          const src = d.snapshotUrl ?? d.artworkUrl
          return (
            <li key={d.linkId} className="flex flex-col gap-1">
              <div className="relative aspect-square w-full overflow-hidden rounded-2xl border border-gray-100 bg-gray-50">
                {/* eslint-disable-next-line @next/next/no-img-element */}
                <img
                  src={src}
                  alt={`${productName} — ${d.name}`}
                  className="h-full w-full object-contain p-2"
                />
              </div>
              <div className="px-1">
                <p className="text-sm text-gray-900">{d.name}</p>
                {d.positionLabel ? (
                  <p className="text-xs text-gray-500">{d.positionLabel}</p>
                ) : null}
              </div>
            </li>
          )
        })}
      </ul>
    </div>
  )
}
```

- [ ] **Step 3: Add the post-pass filter**

In `lib/shop/catalogue-images.ts`, replace the final return of `resolveGalleryImagesForColour`:
```ts
  return Array.from(chosenByView.values())
    .map((entry) => entry.image)
    .sort(compareImages)
```
with:
```ts
  const entries = Array.from(chosenByView.values())
  // D2 blank-image filter: a priority-5 entry is the master-scope, color-null,
  // primary-view base — the "blank product image". Drop it when the colour has
  // at least one colour-specific image (any priority 1–4: catalogue-scope, or a
  // master image colour-matched to the selected swatch). Never empty the gallery.
  const hasColourSpecificImage = entries.some((entry) => entry.priority < 5)
  const filtered = hasColourSpecificImage
    ? entries.filter((entry) => entry.priority !== 5)
    : entries
  const kept = filtered.length > 0 ? filtered : entries
  return kept.map((entry) => entry.image).sort(compareImages)
```

> This is a pure post-pass over the already-built `chosenByView` map values; `imagePriority`'s ladder is untouched (Spec D §6.2). The `entry.priority` field already exists on the map values (`{ image, priority }`).
